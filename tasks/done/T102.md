## T102 — `cli`: arrancar con los proveedores de los repos habilitados

**Estado:** hecho.

**Commit:** `feat(cli): arrancar con los proveedores de los repositorios habilitados (T102)`.

**Qué toca:** `packages/cli/src/boot.ts`, `packages/cli/src/index.ts`, `packages/cli/src/boot.test.ts`.

**Lo que se añade, medido:** el arranque carga también los archivos habilitados de los repositorios, así
que un proveedor instalado ayer está activo al abrir la aplicación y sale en la lista que imprime el
CLI. El orden pasa a ser **migrar → abrir la base → leer la selección → cargar los plugins**, y cada
paso está donde está por un motivo: la selección vive en la tabla de ajustes, así que leerla antes de
migrar es consultar una tabla que puede no existir, y cargar los plugins antes de leerla deja fuera a
todos los de repositorios sin decir nada.

pasan, 0 fallan · `bun run typecheck` 0 · `bun run lint` 0 errores, los 2 avisos de `main`. Medido
mutando: pasando la lista vacía al cargador falla 1; invirtiendo el orden —abrir la base y leer la
selección antes de migrar— fallan 2, las dos con `SQLiteError: no such table`, que es lo que le pasaría
al usuario. Control: 0 fallos.

**Nota:** la prueba del orden **no** prepara la base de antemano: la tabla y la ficha las crea el
`migrate` de la prueba. Con una base ya migrada, invertir el orden no se notaría y la prueba no mediría
nada.
