## T164d — El anfitrión no se compila vacío (**tarea insertada**)

**Estado:** hecho en lo que se puede medir aquí; el árbol de Rust lo compila el CI.

**Commit:** `fix(package): el anfitrión exige el servidor y la prueba dice por qué falla (T164d)`.

**Por qué se inserta:** el instalador de Windows del run `40056709072` abrió una ventana y **no
quedó ningún proceso `nn-anime`**. Eso es el aviso de fallo, no la aplicación. La causa más probable
es un anfitrión compilado sin el servidor dentro; el síntoma aparecía en el instalador, lejos del
sitio donde se puede arreglar.

**Qué entra:**
- `scripts/package/desktop.ts` pasa `NN_ANIME_EXIGIR_SERVIDOR=1` al compilar el anfitrión **en
  Windows** (en macOS y Linux no: allí el servidor viaja al lado).
- `desktop/src-tauri/build.rs`: con esa variable puesta, si no encuentra el servidor **falla la
  compilación** con la ruta y el error, en vez de generar `SERVIDOR = &[]`. También declara
  `cargo:rerun-if-env-changed` para que el cambio de variable no se quede en caché.
- `packaging/windows/probar-instalador.ps1`: si no hay servidor, vuelca el `desktop.log` y los
  ejecutables extraídos en `bin` antes de fallar. La próxima vez el error dice **por qué**, no sólo
  que hay cero procesos.
- Guardas en `scripts/desktop.test.ts` para las tres cosas.

**Verificación en esta máquina:** `bun run typecheck` 0 · `bun run lint` 0 (3 advertencias previas) ·
`bun test scripts/desktop.test.ts` **47 pasan** · el `.ps1` parsea sin errores.

**Lo que NO está verificado:** que el anfitrión compile con la variable y que el instalador arranque
el servidor. Eso lo mide el siguiente run de Windows; si `build.rs` no encuentra el servidor, el
fallo saldrá ahora en «Compilar el anfitrión» con la ruta delante.
