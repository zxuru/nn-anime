## T252 — renombrar el producto a RoNa

**Estado:** hecho. **El árbol de Rust no se pudo compilar en esta máquina** (`cargo test` muere
compilando `ring` por el `cl.exe` del entorno, no por el código); lo mide el CI.

**Commit:** `refactor: renombrar el producto a RoNa (T252)`.

**Qué entra:** el nombre visible y el interno cambian a la vez. Paquetes `@nn-anime/*` → `@rona/*`,
raíz `rona`, CLI `rona`, anfitrión `rona-desktop`, shim `bin/rona`; entorno `NN_ANIME_*` → `RONA_*`;
base `nn-anime.db` → `rona.db`; carpeta de datos `nn-anime-data` → `rona-data` y, en Linux/macOS,
`~/.local/share/rona`, `~/.config/rona` y `~/.cache/rona`; Tauri `io.github.zxuru.rona` con
`productName` «RoNa»; updater y GHCR a `zxuru/rona`; Docker, compose, CI, docs, interfaz, user
agents y las claves `rona:` de `localStorage` y del evento de ocultar la ventana.

**Migración de datos:** `migrateLegacyDirs` (`packages/core/src/config.ts`) traslada las carpetas
del nombre anterior y renombra la base antes de crear nada; `entorno.rs` hace lo mismo en Windows
(hermana `rona-data` y carpeta de la instalación antigua), en macOS/Linux y en modo portable. Si el
traslado falla, no se arranca con una base vacía. Lo miden dos pruebas nuevas en `config.test.ts` y
dos en `entorno.rs`; la de `renombrar_base` comprueba que no pisa una base que ya tenga el nombre
nuevo.

**Verificación:** `bun run typecheck` 0 · `bun run lint` 0 errores (los 32 avisos de
`noReactStringRefs`/`noDescendingSpecificity` ya estaban en `main`) · `bun test` 3901 pasan, 0
fallan · `bun install --frozen-lockfile` sin cambios · `cargo fmt --check` 0. `docs/specs/
SPEC-nn-anime.md` pasa a `SPEC-rona.md`, y la skill de frontend a `frontend-rona`.

**Nota:** el remoto de GitHub y el paquete de GHCR **siguen llamándose `zxuru/nn-anime`**; el código
ya apunta a `zxuru/rona`. Hay que renombrar el repositorio en GitHub a `rona` antes de la próxima
release, o el updater y el `docker pull` darán 404. El remote local puede quedarse: GitHub redirige.
