## T164e — El Cargo.toml en release-please y el listón sin servidor (**tarea insertada**)

**Estado:** hecho.

**Commit:** `fix(release): el Cargo.toml del anfitrión en release-please y el listón sin servidor (T164e)`.

**Qué entra:**
1. **`release-please-config.json`** añade `desktop/src-tauri/Cargo.toml` como `extra-files` de tipo
   `toml`, `jsonpath: "$.package.version"`. Sin eso, el primer PR de release subiría los diez
   `package.json` y dejaría atrás la versión del anfitrión; `scripts/desktop.test.ts` compara las dos
   y el PR quedaría en rojo **antes** de publicar nada. La prueba de `scripts/package.test.ts` ahora
   separa los nueve paquetes del `Cargo.toml` y comprueba su entrada.
2. **`ci.yml`**: el trabajo `desktop` —el que mide el árbol de Rust— compila con
   `desktop:build --sin-servidor`. El trabajo `empaquetado` sigue llamando a `desktop:build` a secas,
   que en Windows **exige** el servidor. Sin esta separación, el listón del anfitrión se compilaba sin
   servidor y la nueva guarda de T164d lo frenaba: era un falso positivo del trabajo de medición, no
   un defecto del empaquetado.

**Verificación en esta máquina:** `bun run typecheck` 0 · `bun run lint` 0 (3 advertencias previas) ·
`bun test scripts/desktop.test.ts scripts/package.test.ts` en verde. La entrada TOML se validó contra
el esquema publicado de `release-please` (`type: toml`, `jsonpath`).

**Lo que NO está verificado:** que `release-please` escriba el TOML en su primer PR. Se verá al
fusionar el primer PR de release; si el formato no fuera el que espera, el test de versión del
anfitrión lo dirá antes de publicar.
