## T251 — publicar sólo artefactos portables

**Estado:** hecho. **El árbol de Rust no se pudo compilar en esta máquina** (`cargo check` muere
compilando `ring` por el `cl.exe` del entorno, no por el código); lo mide el CI.

**Commit:** `feat(package): publicar solo artefactos portables (T251)`.

**Qué entra:** se retiran todas las opciones de instalador. Windows publica sólo
`nn-anime-<v>-windows-x64.exe` (con `.sig` y `latest.json`), macOS un `.zip` con el `.app` y Linux el
AppImage. Desaparecen NSIS/`tauri-bundler`, el `.dmg` con `hdiutil`, `nfpm` (`.deb`/`.rpm`),
`desktop:installer`, `--only-installer`/`--skip-installer`, `probar-instalador.ps1` y el icono del
asistente. El updater de Windows se queda con el reemplazo en sitio y pierde la reserva NSIS; Rust ya
no distingue copia instalada de portable (`entorno::instalada` y el plugin de proceso se van).

**Verificación:** `bun run typecheck` 0 · `bun run lint` 0 (32 avisos previos en `packages/web`) ·
`bun test` 3899 pasan, 0 fallan · `cargo fmt --check` 0 · `cargo metadata --locked` 0.
`latest.json` se prueba con `scripts/package.test.ts` (las dos entradas apuntan al mismo `.exe`) y las
guardas de `scripts/desktop.test.ts` fallan si vuelve el `.nsi`, `nfpm.yaml`, `probar-instalador.ps1`
o `desktop:installer`.

**Nota:** `cargo check` local no termina por `ring`/`cl.exe` (entorno, no código); el trabajo
`desktop` del CI es la medición de compilación. `bun run lint` sigue mostrando los 32 avisos de
`packages/web` que ya estaban en `main`.
