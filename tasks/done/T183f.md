## T183f — las rutas de descargas (roadmap 1.3f)

**Estado:** hecho. El motor ya se puede usar por HTTP.

**Commit:** `feat(server): las rutas de descargas (T183f)`.

**Verificación:** `bun run typecheck` 0 · `bun run lint` 0 errores (27 avisos anteriores) ·
`bun test packages/server` **686 pasan, 0 fallan** (4 nuevas de descargas).

**Medido mutando:** sin `insideRoot` la ruta del archivo podría salir de la carpeta; sin el rango el
`GET /file` devolvería el archivo entero; sin la comprobación de `capabilities.download` se podría
descargar de una fuente que no lo permite; sin el 409 de `segments` se pediría un MP4 que no existe.

**Nota:** `POST /api/downloads` valida la referencia, exige `capabilities.download`, crea la fila y
la encola. `GET /api/downloads` lista; `pause`, `resume` y `DELETE` hablan con la cola; `GET
/api/downloads/:id/file` sirve MP4 con `Range` y `content-range`, y rechaza segmentos o descargas a
medias. El `resolve` del servidor usa `container.resolveStream` con modo `sub`. La cola se arranca
al montar la app y las rutas sólo existen si hay `downloadsDir` o `paths.dataDir`; en pruebas se
inyecta `downloadFetchImpl`.
