**Estado:** hecho, salvo el E2E real de instalación (necesita la release publicada).

**Commit:** `feat(desktop): auto-actualización con el updater de Tauri (T189)`.

**Verificación:**
- `cargo clippy --offline --locked --all-targets -- -D warnings`: 0 avisos.
- `cargo fmt --check`: limpio.
- `tsc --noEmit`: 0 errores (incluye `desktop/ui/actualizacion.ts`).
- `biome check .`: 0 errores; 28 avisos, los mismos que `main` (medido en el checkout de
  integración), ninguno en los archivos tocados.
- `bun test scripts/package.test.ts scripts/desktop.test.ts`: 75 pasan, 0 fallan.
- **E2E local del check**: `latest.json` propio (versión 9.9.9, firmado con `tauri signer sign
  --app-version 9.9.9`) servido por HTTP, anfitrión de depuración con `LOCALAPPDATA` aislado. El
  registro dice `actualización: hay una versión nueva: 9.9.9 (instalada 0.3.1)` y la ventana
  `nn-anime — actualización` aparece visible. El E2E **encontró un fallo real**: `core:default` no
  incluye `window.show`, y el permiso se añadió a `capabilities/actualizacion.json`.
- **Lo que el E2E local no mide**: descarga, verificación de firma e instalación. La descarga no se
  pudo disparar porque el sandbox deja el proceso a integridad `Low` y WebView2 no acepta entrada
  sintética; el `payload.bin` tampoco es un instalador NSIS. Se mide en el E2E real: instalar un
  0.0.1 con el setup y publicar una versión mayor, que es el paso que el usuario hará tras crear
  los secretos.

**Nota:** la ventana de actualizaciones sólo se crea en Windows mientras macOS y Linux no publiquen
bundles del updater. El `.nsi` escrito a mano y `scripts/package/windows.ts` se han borrado; el
instalador de Windows lo arma `tauri-bundler` con `tauri-action`. La clave privada está en
`<raíz>/.tmp/nn-anime-updater/` (ignorado por git) y hay que moverla fuera del repositorio; sin ella
no se pueden firmar releases futuras.
