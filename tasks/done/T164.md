## T164 — El archivo único en la release automática

**Estado:** hecho en lo que se puede medir aquí. **El `.exe` no se ha compilado ni ejecutado en esta
máquina** —`cargo` está bloqueado por la directiva de Control de aplicaciones y no hay `makensis`—; lo
compila y lo ejecuta el CI, y la primera release real queda pendiente de aceptación.

**Commit:** `feat(release): el archivo único y un solo publicador (T164)`.

**Qué entra:**
- `release.yml`: el orden es ahora **servidor → firmar servidor → anfitrión (lo embebe) → firmar
  anfitrión → `package:unico` → instalador**, y el PE del `.exe` único se mide junto al del servidor y
  el anfitrión. La firma de Windows se parte en dos para que el servidor firmado sea el que viaja
  dentro.
- `ci.yml`: la misma cadena en cada push (`--skip-installer` → `desktop:build` → `package:unico` →
  `--only-installer`), con la comprobación de integridad/ACL que traía `desktop.yml`.
- `desktop.yml` **se elimina**: era un segundo publicador y una segunda ruta de compilación.
- `scripts/package.ts`: si el anfitrión de Windows es más viejo que el servidor, `bun run package` se
  niega a armar el instalador. Antes lo producía arrancando sin interfaz.
- `packaging/windows/probar-instalador.ps1`: espera **un solo** ejecutable, comprueba que el servidor
  se extrajo a `%LOCALAPPDATA%\nn-anime\bin\<versión>`, mide la X ocultando en la bandeja y limpia los
  procesos; ya no espera `%APPDATA%` ni un `nn-anime.exe` suelto.
- Guardas nuevas en `scripts/desktop.test.ts`: nombre del archivo único, `comprobarOrden` con fechas
  reales, orden de los pasos de `release.yml` y `ci.yml`, un solo publicador, y las expectativas del
  guion del instalador.

**Verificación en esta máquina:** `bun run typecheck` **exit 0** · `bun run lint` **exit 0** (las
mismas 3 advertencias previas) · `bun test scripts/desktop.test.ts` **46 pasan, 0 fallan** ·
`bun run version:check` 0.1.0 · los workflows se leen y su orden se comprueba en las pruebas.
