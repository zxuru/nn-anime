**Medido con mutación de la implementación, como pide el listón:**

- Con `limpiar` borrando también los worktrees **que git tiene registrados**, el caso «borra el

- Control con el código como está: 0 fallos.

**Lo que hace el comando:** `bun run scripts/agente.ts limpiar` dice qué va a borrar y no borra nada;
con `--si` borra. Un resto —un directorio de `.worktrees/` que git no tiene registrado— **se borra
sólo** cuando su rama ya está integrada en `main` y dentro no hay ni un archivo que su rama no tenga,
con el mismo contenido. Se **conserva**, y se dice por qué, cuando la rama no está integrada, cuando
hay cambios sin commitear (`sin versionar:`, `modificado:`), cuando dentro hay más de 500 archivos
—no se sabe qué guarda— o cuando no hay rama contra la que comparar. Un worktree al que le quitaron
los metadatos de git se puede borrar si su rama está integrada: es el caso que dejó 77 directorios
sin podar.

**Nota:** los restos no se podan solos: `limpiar` es el que lo hace, y hasta que se ejecute,
`.worktrees/` sigue teniendo lo que dejaron las sesiones ya integradas. El script también lo dice en
`estado`, que ahora termina con el número de directorios sin registrar.
