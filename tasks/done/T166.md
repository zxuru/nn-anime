## T166 — el Cargo.lock del anfitrión sigue la versión

**Estado:** hecho.

**Commit:** `fix(release): el Cargo.lock del anfitrión sigue la versión (T166)`.

**Verificación:** `cargo metadata --manifest-path desktop/src-tauri/Cargo.toml --locked --no-deps
--format-version 1 --offline` sale 0 y declara `nn-anime-desktop@0.2.0` · `bun run version:check`
dice «version 0.2.0: la raíz y los 9 paquetes coinciden» · `git diff --check` limpio.

El fallo que corrige, medido en el run `40126389503` de la release: los cuatro instaladores fallaron
en «Compilar el anfitrión» con `cannot update the lock file …/Cargo.lock because --locked was passed
to prevent this`. `release-please` subió `desktop/src-tauri/Cargo.toml` a 0.2.0, pero el
`Cargo.lock` seguía en 0.1.0 y `cargo build --release --locked` no puede actualizarlo.

**Nota:** el lock se actualiza a mano porque `cargo metadata --offline` no resuelve el índice en este
entorno; con la línea del paquete a 0.2.0, `--locked` ya valida. Queda pendiente decidir si
`release-please` debe actualizar el lock en cada release o si `release.yml` lo regenera antes de
compilar; no se toca aquí. Para publicar 0.2.0 hay que mover el tag `v0.2.0` a este commit y
empujarlo: el tag creado con `GITHUB_TOKEN` no disparó `release.yml`, así que el workflow se lanzó a
mano y sin el lock corregido falló.
