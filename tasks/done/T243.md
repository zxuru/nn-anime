## T243 — el updater fuera de Windows

**Estado:** hecho (el límite queda declarado y visible en la aplicación; no se publican entradas
`darwin-*`/`linux-*`).

**Commit:** `feat(desktop): el límite del updater, visible fuera de Windows (T243)`.

**Qué toca:** `desktop/src-tauri/src/{main,actualizacion,tray}.rs`, `desktop/ui/{actualizacion.ts,actualizacion.html}`,
`README.md`, `docs/release.md`, `scripts/desktop.test.ts` (la guarda del menú pasa de tres a cuatro
opciones y se añade la del límite).

**Lo que cambia, por plataforma.** El módulo `actualizacion` deja de estar bajo `#[cfg(windows)]`: la
ventana existe y se crea en las tres plataformas, y la abanica «Buscar actualizaciones» de la
bandeja, que ahora es la cuarta opción en todas. Rust pasa a la página `automatica = cfg!(windows)`;
la página **no llama a `check()`** donde es falso, y en su lugar dice que la actualización automática
sólo está disponible en Windows y deja el enlace a la release (`/releases/latest`) para descargar a
mano. No aparece «Actualizar ahora» y `actualizar()` también se protege. En Windows el
comportamiento no cambia: mismo texto («Versión portable»), misma comprobación, mismo botón, mismo
reemplazo. Lo que queda detrás de `cfg(windows)` es exactamente el reemplazo: `instalar_portable`
(que tampoco se registra fuera), `temporal_de`, `reemplazar`, `verificar`, `version_firmada`,
`esperar_reemplazo`, `argumento`, `esperar_a` y `limpiar_viejos`; `Contexto.pubkey` y sus tipos
asociados también, para no dejar campos sin leer que `clippy -D warnings` convertiría en rojo. La
capability `capabilities/actualizacion.json` no se tocó y no hay IPC nueva: `registrar_actualizacion`
(y no `instalar_portable`) es el único comando que se registra en macOS/Linux.

**Verificación:** `bun run desktop:ui` compila (9 módulos) · `bun run typecheck` exit 0 ·
`bun run lint` exit 0 (0 errores; 32 avisos previos) · `bun test desktop/ui scripts/desktop.test.ts
packages/web/src/docs.test.ts` **72 pasan, 0 fallan** (3 archivos) · `cargo fmt --check` exit 0.
Medido mutando la prueba nueva: cambiar `if (!automatica)` por `if (automatica)` en
`actualizacion.ts` la pone en rojo (51 pasan, 1 falla) y el código vuelve a su sitio después.
**`cargo check` no se pudo ejecutar en este entorno:** el Control de aplicaciones de Windows bloquea
los build scripts recién compilados con «Una directiva de Control de aplicaciones bloqueó este
archivo. (os error 4551)». Se probó el `target` del worktree, `.tmp/t243-target` y el `target` de la
raíz: el primero falla en `getrandom`, el segundo en `icu_normalizer_data`, y el tercero llega a
compilar dependencias pero se para en el build script propio de `rona-desktop`; en el tercero, además,
`ring` reventó al invocar `cl.exe` desde un build script. Un binario de sonda de `rustc` en esas
mismas rutas sí se ejecuta, así que el bloqueo es de los ejecutables que produce `cargo`. No se pudo
medir la compilación de macOS/Linux en local.

**Nota:** la compilación real de macOS y Linux la mide el trabajo `desktop` del CI con
`bun run desktop:check`, que corre `fmt`, `clippy -D warnings` y `cargo test` en las tres. Aquí sólo
queda la revisión estática del `cfg`, y se dice. `docs/specs/SPEC-desktop.md` sigue describiendo la
bandeja con «tres opciones» y no lista `actualizacion.rs` en su árbol; no se toca porque es un spec y
este task no es su dueño: queda para quien lo integre. `tauri-plugin-updater` se registra en las tres
plataformas (ya estaba declarado para ellas), pero la página sólo lo usa en Windows.
