## T249 — el lint falla con la versión de Biome que fija el lockfile

**Estado:** hecho.

**Commit:** `chore(repo): el esquema de Biome y lo que su versión nueva enseña (T249)`.

**Verificación:** `bun run typecheck` 0 errores · `bun run lint` **0 errores**, 35 avisos (los que
quedan son `noReactStringRefs` en pruebas y `noDescendingSpecificity` en el CSS) · `bun test`
**3668 pasan, 0 fallan** (216 ficheros).

**El defecto, y por qué estaba escondido.** `bun.lock` fija `@biomejs/biome` en **2.6.5**, pero el
`node_modules` de esta máquina tenía la **2.6.3**: con la versión vieja, `biome check .` salía con 0
errores y todo parecía en verde. Con la versión que el lockfile fija —la que instala el CI con
`bun install --frozen-lockfile`— salen **tres** cosas:

1. `biome.json` declara el esquema de la **2.6.3**, y la CLI de la 2.6.5 no lo acepta: **error**.
   Con la 2.6.5 el `$schema` pasa a `https://biomejs.dev/schemas/2.6.5/schema.json`.
2. `packages/web/src/features/guia/useGuia.ts:19` importa `type RouteName` y **no lo usa**: la regla
   `noUnusedImports` es de las que fallan el lint. El import sobra y se va.
3. `packages/web/src/features/search/search.test.tsx` **no estaba formateado** como lo quiere la
   2.6.5: dos llamadas con el argumento en varias líneas donde cabe en una.

Con las tres corregidas, `bun run lint` sale con **0 errores**, que es lo que el CI exige.

**El `bun.lock` también va.** Las versiones de los paquetes del workspace estaban en **0.7.0**,
cuando sus `package.json` dicen **0.8.0** desde la última release: el lockfile no cuadtaba con el
manifiesto. `bun install --frozen-lockfile` lo tolerate, pero un lockfile que miente no es un
cache: es una fuente de verdad que dice otra cosa.

**Nota:** esta tarea no estaba en `tasks/deuda.md`: salió de que el `node_modules` de la máquina
tenía una versión de Biome que el lockfile no fijaba, y el lint verde de local **tapaba** un lint
rojo en el CI. El id **T249** es el siguiente libre del lote reservado.
