## T100 — `server`: descargar un repo de GitHub dentro de la lista blanca

**Estado:** hecho.

**Commit:** `feat(server): descargar un repo de GitHub dentro de la lista blanca (T100)`.

**Qué toca:** `packages/server/src/github.ts` (nuevo), `packages/server/src/github.test.ts` (nuevo).

**Lo que se añade, medido:** `downloadGithubRepo` resuelve la rama por defecto si la dirección no trae
referencia, pide el árbol recursivo, descarga cada archivo por `raw.githubusercontent.com` y lo deja en
el destino —en un directorio temporal hermano que se mueve al final, así que un fallo a mitad no toca lo
que ya había—. La subcarpeta de la dirección **filtra** el árbol; las rutas guardadas siguen siendo las
del repositorio entero.

**Verificación:** `bun test packages/server` 407 pasan, 0 fallan · `bun run typecheck` 0 · `bun run lint`
0 errores, los 2 avisos de `main`. Medido mutando: sin la lista blanca de hosts falla 1 —la prueba pide
un host ajeno por redirección, y el host ajeno no llega a pedirse—, sin el tope de archivos 1, sin la
comprobación de árbol truncado 1, sin `isSafeRepoPath` 1 (la ruta hostil llega a `confine`, que aborta
la instalación). Control: 0 fallos. `confine` tiene además su propia prueba: `../fuera.ts` y
`/otro/lado.ts` no tienen archivo.

**Nota:** la lista blanca se aplica **en cada salto** y no sólo en la primera URL, porque una
redirección es la forma más fácil de saltársela: va dentro del `fetch` que `fetchAllowed` usa en cada
salto, así que el host se comprueba justo antes de abrir la conexión.

**Nota:** el tope por archivo (512 KiB) **salta** el archivo en vez de fallar —un repo puede llevar una
portada grande sin que eso impida instalar sus proveedores—; los topes de número de archivos y de
total sí son un error, porque instalar la mitad sin decirlo deja un proveedor que falla por un archivo
que no está, lejos de la causa.
