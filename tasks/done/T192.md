## T192 — el listado de carpetas del selector

**Estado:** hecho.

**Commit:** `feat(server): el listado de carpetas del selector (T192)`.

**Verificación:** `bun run typecheck` 0 · `bun run lint` 0 errores (28 avisos anteriores) ·
`bun test packages/server` **701 pasan, 0 fallan**. Medido mutando: dejar entrar los archivos rompe 2
pruebas; ofrecer unidades fuera de Windows rompe 1; quitar el tope de 500 rompe 1.

**Nota:** `GET /api/downloads/dirs?path=` devuelve la carpeta listada, su padre (`null` en una raíz),
las carpetas que contiene y, en Windows y sólo en una raíz, las unidades a las que saltar. Sin `path`
lista la raíz de descargas, que es donde abre el selector. El módulo es
`packages/server/src/downloads/dirs.ts` y no lanza: devuelve el motivo —`invalida`, `no-existe`,
`sin-permiso`— porque el motivo es lo que se traduce a 400, 404 o 403 y lo que la pantalla cuenta.
Se leen nombres de carpeta y **nunca** contenido de archivo; la superficie queda pendiente de
`SECURITY.md`, que la cierra el integrador.

**Lo que encontró la prueba:** el primer filtro dejaba pasar los archivos —`esCarpeta` devolvía
`true` para cualquier entrada que no fuera un enlace— y la prueba del orden lo cazó antes del
commit. Ahora una entrada entra si `isDirectory()`, o si es un enlace cuyo destino lo es.

**Lo que no se pudo medir:** una carpeta sin permiso de lectura (haría falta montar ACL de Windows, y
la prueba sería del sistema y no del código). Queda cubierta por el mapeo de `EACCES`/`EPERM` a 403,
que no se ejercita.
